Saya ingin membuat sebuah aplikasi desktop untuk Windows menggunakan Python yang berfungsi sebagai **KMZ/KML to Excel Converter & Intelligent Classifier**.

Tujuan utama aplikasi ini adalah membaca file `.KMZ` yang berasal dari Google Earth Pro, mengambil seluruh data `Placemark`, nama titik, koordinat, struktur folder, dan informasi terkait lainnya, kemudian mengklasifikasikan data tersebut secara otomatis ke dalam beberapa worksheet Excel.

Saya memiliki contoh file KMZ nyata bernama:

`IF-JMB-MOCNPhase1-DF010.kmz`

Gunakan file contoh tersebut sebagai bahan untuk memahami struktur data KMZ/KML. Jangan mengasumsikan bahwa semua data selalu memiliki struktur yang sama. Program harus dibuat cukup fleksibel terhadap variasi nama folder, nama Placemark, format penamaan titik, dan struktur KML.

## 1. Fungsi utama aplikasi

Aplikasi harus memiliki GUI sederhana sehingga pengguna tidak perlu menjalankan command line secara manual.

Alur pengguna:

1. Jalankan aplikasi.
2. Muncul window aplikasi.
3. Terdapat tombol:

   * `Pilih File KMZ`
   * `Proses / Convert`
   * `Buka Folder Output`
4. Pengguna memilih file `.kmz`.
5. Aplikasi membaca dan menganalisis isi KMZ.
6. Aplikasi mengekstrak file `.kml` di dalam KMZ secara otomatis.
7. Program membaca seluruh struktur Folder dan Placemark.
8. Program mengambil:

   * Nama Placemark
   * Folder induk
   * Latitude
   * Longitude
   * Description jika tersedia
   * Informasi lain yang relevan
9. Program melakukan intelligent classification.
10. Program menghasilkan satu file `.xlsx`.
11. File Excel harus memiliki worksheet:

* `Tiang`
* `Acc Tiang`
* `Slag Kabel`
* `Closure`
* `OTB, ODP`

Semua worksheet tersebut harus tetap dibuat meskipun tidak ada data untuk kategori tersebut.

## 2. Struktur Excel

Setiap worksheet menggunakan kolom:

`NO | MARKING | LAT | LONG | REMARK`

Header utama Excel:

`DATA KOORDINAT TIANG 7m,9m & TIANG EXISTING`

Di bawah header utama tampilkan nama file KMZ yang sedang diproses.

Data harus dibuat dalam format Excel yang rapi dan mudah dibaca.

Gunakan:

* bold untuk header
* border pada tabel
* automatic column width
* alignment yang sesuai
* freeze pane jika diperlukan
* format koordinat yang konsisten

## 3. Sistem klasifikasi

Program tidak boleh hanya bergantung pada satu nama tertentu.

Gunakan kombinasi:

* nama Placemark
* nama Folder
* struktur parent folder
* description
* pola teks
* keyword
* regex

Normalisasi teks terlebih dahulu:

* ubah menjadi lowercase
* trim spasi
* normalisasi karakter yang tidak diperlukan

### Kategori Tiang

Identifikasi titik sebagai kategori `Tiang` jika terdapat indikasi seperti:

* `NP`
* `TE`
* `Pole`
* `New Pole`
* `Existing Pole`

Tetapi sistem harus lebih fleksibel terhadap variasi penulisan.

Jika sebuah titik merupakan Tiang, titik tersebut juga harus masuk ke worksheet:

`Acc Tiang`

Jadi satu Placemark boleh masuk ke lebih dari satu worksheet apabila memang memenuhi beberapa kategori.

## 4. Klasifikasi jenis Tiang

Untuk worksheet `Tiang`, tentukan REMARK berdasarkan informasi yang tersedia.

Contoh:

Jika ditemukan:

`Pole 7`

maka:

`New Pole 7M`

Jika ditemukan:

`Pole 9`

maka:

`New Pole 9M`

Jika terdapat:

* `Existing`
* `Old`
* `Existing Pole`

maka:

`Pole Existing`

Jika terdapat pola seperti:

`NP7`
`NP 7`
`NP-7`
`NP_7`

maka program harus dapat mengenalinya sebagai:

`New Pole 7M`

Begitu juga untuk:

`NP9`
`NP 9`
`NP-9`
`NP_9`

menjadi:

`New Pole 9M`

Jangan hanya membuat regex untuk satu format. Buat regex yang toleran terhadap spasi, underscore, dash, dan variasi penulisan.

Jika sistem menemukan NP dengan ukuran lain, misalnya NP8, jangan membuang data. Gunakan:

`New Pole 8M`

atau sesuai angka yang ditemukan.

## 5. Kategori Slag Kabel / Slack

Program harus mendeteksi variasi seperti:

* `slag`
* `slack`
* `slak`
* `slk`
* `hanger`
* `hgr`
* dan variasi penamaan lain yang secara jelas mengindikasikan Slack Support.

Jika terdeteksi sebagai kategori tersebut, masukkan ke worksheet:

`Slag Kabel`

MARKING default:

`Slack Support`

Jika nama atau folder mengindikasikan titik existing, misalnya:

* `EX`
* `EKS`
* `OLD`
* `EXIST`

maka REMARK:

`Eks Slack Support`

Jika tidak:

`New Slack Support`

## 6. Kategori Closure

Deteksi variasi:

* `closure`
* `clo`
* `cls`
* `clsr`

dan variasi yang relevan.

Masukkan ke worksheet:

`Closure`

MARKING:

`CL24`

Jika merupakan existing berdasarkan nama/folder/description, gunakan:

`Eks Closure`

Jika bukan existing:

`New Closure`

## 7. Kategori OTB / ODP

Deteksi keyword seperti:

* `OTB`
* `ODP`
* `ACPBD`
* `DP`

dan variasi penamaan yang relevan.

Masukkan data ke:

`OTB, ODP`

Untuk kategori ini, jangan sembarangan mengganti MARKING.

Jika Placemark memiliki `<description>`, gunakan isi description sebagai MARKING.

Jika description kosong, gunakan nama Placemark.

REMARK dapat menggunakan nama asli Placemark atau informasi yang paling relevan dari data sumber.

## 8. Multi-classification

Ini sangat penting.

Satu Placemark BOLEH masuk ke lebih dari satu worksheet apabila memenuhi lebih dari satu kategori.

Contoh:

Jika suatu titik memiliki nama/folder yang menunjukkan bahwa titik tersebut merupakan:

`NP7 Pole`

maka titik tersebut masuk ke:

`Tiang`

dan:

`Acc Tiang`

Jangan menggunakan sistem `if / elif` yang membuat satu titik hanya boleh masuk satu kategori.

Gunakan sistem classification berbasis `set/list` sehingga beberapa kategori dapat aktif sekaligus.

## 9. Folder hierarchy

Saat membaca KML, jangan hanya membaca nama Placemark.

Simpan juga seluruh hierarchy Folder.

Contoh:

Document
→ Backbone
→ Pole
→ Existing
→ Placemark

Gabungkan nama folder tersebut sebagai konteks untuk klasifikasi.

Jika nama Placemark tidak cukup jelas tetapi nama Folder memberikan informasi kategori, gunakan informasi Folder tersebut.

Contohnya:

Folder:

`Pole Existing`

Placemark:

`P-001`

maka sistem tetap dapat mengenali bahwa titik tersebut merupakan Existing Pole.

## 10. Koordinat

Dari elemen KML:

`<coordinates>longitude,latitude,altitude</coordinates>`

ambil:

* longitude
* latitude

Masukkan ke Excel dengan urutan:

`LAT`
`LONG`

Jangan sampai longitude dan latitude tertukar.

Altitude tidak perlu dimasukkan ke Excel kecuali memang diperlukan.

Jika koordinat rusak atau tidak valid, jangan membuat aplikasi crash.

Lewati data tersebut dan catat sebagai warning/log.

## 11. Penanganan data kosong

Jika suatu worksheet tidak memiliki data, worksheet tetap harus dibuat.

Contoh:

`Closure`

tetap dibuat walaupun jumlah datanya 0.

Header dan format tetap ada.

## 12. Validasi dan error handling

Aplikasi harus menangani:

* file bukan KMZ
* KMZ corrupt
* KMZ tidak memiliki KML
* KML tidak valid
* Placemark tidak memiliki nama
* Placemark tidak memiliki koordinat
* koordinat tidak valid
* description kosong
* Folder kosong
* nama file mengandung spasi
* nama file mengandung karakter khusus
* duplicate Placemark
* KML menggunakan namespace
* struktur KML yang tidak standar

Jangan membuat aplikasi crash hanya karena satu Placemark bermasalah.

Gunakan logging atau status informasi pada GUI.

## 13. Output filename

Jika file input:

`IF-JMB-MOCNPhase1-DF010.kmz`

maka output default:

`Converted_IF-JMB-MOCNPhase1-DF010.xlsx`

Simpan output pada folder yang mudah ditemukan.

Berikan pilihan kepada pengguna untuk menentukan lokasi output apabila memungkinkan.

Jangan menghapus data hanya karena program tidak mengenali kategorinya.

Jika tidak dikenali, simpan sebagai log/warning agar dapat diperiksa pengguna.
